# dsh-erp

面向 ERP 网站的本地学习与辅助操作插件，目标宿主锁定为 **dsh 0.1.5 rc2**（官方标签 `dsh-v0.1.5-rc.2`），运行时基线为 **Node.js 24 LTS**。

通过用户登录后的浏览器会话，逐步积累菜单地图、页面结构、字段含义、状态值、业务关系和操作经验。知识可查看、纠正并追溯证据；每次向 ERP 写入业务数据前必须获得用户对具体变更的确认。

## 核心原则

- **效果第一**：用真实 ERP 任务验证选型，语言统一和依赖数量服从完成效果。
- **信任 AI 能力**：自主探索、推理、纠错和积累方法，按需学习，不要求提前编写所有流程。
- **方便单机启动**：用户本机运行 dsh，安装插件即可开始配置与登录；允许包体较大，不要求部署数据库或其他服务。
- **业务写入固定确认**：确认具体业务变更，AI 自主完成批准范围内的必要步骤；内部学习记录自动积累。

## 当前状态

项目处于方案阶段，尚无可安装实现。已核对目标版本的官方架构、模型服务及工具执行管线，实际插件兼容性、浏览器效果和安装体验仍需验证。

## 第一版范围

- 一个 ERP、一个角色和一个业务域。
- 用户登录与人工接管，优先使用只读账号开展学习。
- 菜单地图、页面索引和带证据的字段知识文档。
- 少量可复用查询，以及知识查看、纠正与版本管理。
- 测试环境中的一个受控写入流程，验证确认、中断恢复和结果回读。

## 技术方向

**dsh 原生代理＋TypeScript 插件＋本地 Node 24 工作进程＋SQLite＋本机 Chromium。**

- 复用 dsh 的模型、代理循环、工具管线、审批与会话能力；原生接入，首版不额外增加 MCP 或代理编排框架。
- Playwright 作为首个浏览器执行基础；页面观察、复杂交互和恢复能力优先复用成熟实现，并与 browser-use 做效果对照。
- SQLite 优先采用 `node:sqlite`，保存知识、关系、版本和执行记录；文档与证据放本地文件。
- Node 是唯一主开发路线。只有实测证明成熟 Python 方案持续明显领先且值得承担依赖成本时，才考虑随插件打包执行器，不要求用户管理 Python。
- 本机浏览器窗口支持登录与人工接管；内嵌画面是后续增强，不是第一版前置条件。
