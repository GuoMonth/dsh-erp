# ADR 0004：书签站点、工作区文件夹与可携带分享包

日期：2026-11-04。状态：已接受（产品已确认，#51 已合入）。本决策不发布 npm。本决策不改 [ADR 0001](0001-local-first-ai-erp.md) 的 Node、SQLite 与 dsh 原生基线，也不改 [ADR 0003](0003-controller-bfs-index.md) 的深度 3 索引机制。一键探索只是把那条路径变成首次动作。中文界面是 ERP 助手，英文界面是 Adapt ERP，包名是 `@guosheng_047/dsh-erp`。

## 背景

用户要收藏的是一个 ERP 网站，不是一套身份。今天的桌面向导仍把应用根 `baseUrl` 和账户标签放在添加站点的主表单上；`SystemConfig` 还接受 `tenant` 与 `role`，补丁和更新接口可以写入。入口路径不以 `/` 结尾时，还要另填以 `/` 结尾的应用根。带账号或查询的粘贴会被拒绝，而不是整理成主入口。这是身份向导，不是书签。本决策收起这条主路径。

登录已经留在官方右侧 Sidebar Browser，插件不收密码。会话应明确留给浏览器自己的资料。过期后用户再登录一次，插件只记住书签。

站点与对话已经按「一个对话，一个站点」绑定，跨站不会落到另一份索引。添加站点会在插件数据目录下准备文件夹；向宿主登记 Workspace、创建会话并绑定，发生在用户打开该站点时，而且桌面只恢复其中一段会话。产品要的是添加当时就得到该 ERP 的文件夹，其下再新建或切换子会话，像浏览器收藏夹，而不是先开一段任意对话再事后绑定。

分享的主故事仍是一个 Skill 目录：`SKILL.md` 与 `references/knowledge.json`。那份导出去掉了结构化身份和登录资料，但没有自描述的版本、清单和完整性，也不是接收方按文件选择导入的包。完整私有备份继续走[存储恢复](../storage.md)，二者不能混用。

## 对抗式审查

| 被审查的方案 | 反驳 | 决定 |
| --- | --- | --- |
| 添加时收集账户、租户、角色，并另填应用根 | 用户通常只有一个网址；主路径变成身份向导 | 主路径只收书签 URL。显示名可从主机名带出。身份标签若仍要隔离知识，留到高级或内部范围 |
| 深链原样保存，或拒绝后让用户改到能通过校验 | 一次性票据会进收藏；分开的 `baseUrl` 把整理推回表单 | 粘贴后整理成站点主入口。规则写在下面，本 ADR 不附带代码 |
| 把密码、Cookie 或令牌收进插件，或让 AI 去刮 | 插件不负责登录，也不该成为第二份凭据库 | 不存密码。会话留给 DeepSeek Harness 与浏览器自己的资料。过期后用户再登录 |
| 先开空白对话，再手动绑站点 | 容易绑错；第二个 ERP 会落到同一段对话 | 添加站点即建立该 ERP 的 Workspace 文件夹，其下再新建或切换子会话 |
| 未登录也把探索标成完成 | 登录页不是菜单地图 | 一键探索对齐 ADR 0003。未见已登录界面则暂停。部分结果保持可见 |
| 继续以 Skill 目录为主要分享 | 目录缺少版本、清单和完整性 | 主分享改为本机选择的 zip 包 |
| 把整份备份当分享，或让 AI 读任意文件 | 备份含登录与私人观察；没有版本就无法拒绝读不懂的主格式 | 分享包默认排除登录和不必要的原始私人观察。备份恢复仍是另一条路径 |
| 每次发版锁死全部字段，或完全不设结构 | 前者旧读者打不开；后者无法区分包的种类 | 版本化信封，忽略未知扩展。读者支持 N 与 N−1。更高主版本明确拒绝 |

## 已接受的决策

1. 站点等于书签 URL。用户只粘贴 ERP 网站地址。显示名可空，空则用主机名填上；之后可以改显示名，改名不换成另一个站点。粘贴若是深链，先整理成该站点的主入口，再保存。整理规则是产品政策：只保留 `http` 或 `https`；去掉账号和密码，不回显、不落盘；去掉一次性查询和一次性 hash（登录票据、授权码、跳转状态）；单据、记录和回调收到应用首页，即源站点加上稳定应用根（origin，或 origin 加明确的挂载路径，并以 `/` 结尾）；若该 ERP 的稳定首页本身在 hash 上，保留这个首页，只去掉其中的一次性片段。稳定应用根由这次粘贴得出，主界面不再单列 `baseUrl`。账户标签、租户、角色不作为必填，也不放在主界面上突出。若知识隔离以后仍需要身份标签，只作为高级或内部范围。今天向导和 `SystemConfig` 仍暴露 `baseUrl`、账户、租户和角色，这就是本决策要关掉的缺口。见[配置说明](../system-configuration.md)。

2. 登录留在官方浏览器，插件只保存书签。打开的是未登录的入口。用户在官方右侧 Sidebar Browser 里完成登录；二维码、TOTP、短信和 SSO 都在那里完成，插件不驱动登录。不保存密码。不把 AI 刮取令牌或 Cookie 再写入插件存储当作主设计。会话优先使用 DeepSeek Harness 与浏览器自己的持久化（Cookie、分区的浏览器资料）。过期后用户再登录一次。插件持久化的是书签：入口 URL，以及它和 Workspace 的绑定，相当于浏览器收藏。

3. 一个 ERP 等于一个 Workspace 文件夹。添加站点时自动为该 ERP 建立 DSH Workspace（会话文件夹）。文件夹之下，用户新建或切换子会话。界面隐喻是浏览器收藏夹：ERP 文件夹，下面是子会话。知识与索引留在该 Workspace、该 ERP；跨站不落到另一份索引。现有「一个对话，一个站点」的隔离仍然成立，从事后绑定演进为先有文件夹树。浏览器里谁已登录，仍决定看得见的菜单；文件夹不代替这个范围。实现必须使用当前 dsh 的 session / workspace 原语。桌面客户端今天在打开站点时，若宿主注入了 `workspaces`，会以路径调用其 `create`，再用 session 的 `create({ cwd })` 与 `uiWorkspace.openSession` 打开一段会话。产品要求的是该文件夹下可新建、可切换的子会话。若这些原语还不能表达文件夹中的子会话，记为开放依赖；本 ADR 不假定新的宿主 API。

4. 冷启动提供一键探索。首次运行提供「一键探索 / Start exploring」。它跑核心菜单与结构探索，对齐 [ADR 0002](0002-menu-first-domain-learning.md) 的菜单认知和 [ADR 0003](0003-controller-bfs-index.md) 的控制器深度 3 广度优先：前沿由控制器持有，深度停在 3，一层清空后先写紧凑摘要再放下层。探索得到的索引立即持久化。用户须已经登录；右侧浏览器里还看不到已登录界面时，探索暂停，不对着登录页建索引。部分结果保持可见。未完成的范围标明未完成。还没有摘要的范围仍按 ADR 0003 返回未初始化，不假装已经走完整个 ERP。

5. 分享与导入使用可携带的包。主分享体验改为这份包，取代「分享一个 Skill 目录」。分发渠道（邮件、即时通讯）不在范围内；导入是本机选择文件。包是 zip，根上有自描述的 `manifest.json`：`format` 与 `schemaVersion`、生产者应用和版本、不含秘密的站点公开元数据（整理后的入口、显示名、工作区标识）、内容清单、完整性哈希。载荷优先是 `knowledge.jsonl`，一行一条记录，带 `kind` 和该记录自己的版本；证据可选，由清单里的哈希引用。默认分享排除登录、Cookie、凭据，以及分享所不需要的原始私人观察。自由文本仍可能含有业务信息，导出前由用户过目；插件不上传。导入把记录标为 `needs-review` 与 `interpreted`，重新绑定到接收方自己的 Workspace，不执行包内代码，不授予接收方 ERP 的登录或写入权限。现有存储备份与 `restoreBackup` 仍是完整私有备份的恢复路径。分享包不是备份，备份也不是分享包。见[原生操作与分享](../native-and-sharing.md)和[存储说明](../storage.md)。

6. 跨版本读取采用版本化信封，并忽略未知扩展。不采用每次发版都锁死的全字段结构，也不把「让 AI 读懂任意一块数据」当作格式。manifest 与每一行 JSONL 都带 `format` 和 `schemaVersion`。稳定核心是结构化的：入口 URL、workspace 标识、`kind`、引用。解释层是半结构化的自然语言摘要，供 AI 阅读；缺摘要仍可按核心字段导入，摘要措辞变化不单独构成新的主版本。同一 `format` 下，读者支持当前主版本 N 与上一主版本 N−1。本决策把第一版定为 `schemaVersion: 1`；在第 2 版出现之前，读者只接受 1。未知键忽略。未知 `kind` 跳过，并给出明确警告，不中止其余已认识的记录。不支持的更新主版本或无法识别的 `format` 整包拒绝，给出明确错误，不部分写入。本机 SQLite 继续沿用存储文档的做法：先做经校验的备份，再在事务里迁移。分享包的 `schemaVersion` 与数据库 schema 版本分开，互不代替。纯自由文本、没有 `format` 和 `kind` 的包，以及把每一发版的内部字段都放进必填结构的包，都不作为本格式。

7. 本 ADR 划定的边界。确认前，当前向导、`SystemConfig`、Skill 导出和存储恢复保持文档中的行为。确认后的实现 PR 再改这些路径。不改变 ADR 0001 的 Node 24、`node:sqlite`、本机浏览器、dsh 原生工具与审批。不改变 ADR 0003 的控制器前沿、深度 3、摘要加一页叶子；一键探索产品化的是这条路径。不要求本变更为了本决策发布 npm。

## 后果与边界

主添加界面变短：一个网址，一个可选的显示名，然后在右侧浏览器登录。深链不再靠用户手填应用根。账户、租户和角色若从主路径拿掉，今天用应用根加上这些标签区分索引的做法要另作迁移；确认后的实现须保留已有站点的持久 ID，避免一次升级把原索引拆成新站点。显示名继续只是标签。

文件夹先于对话。未进入该 Workspace 的对话读不到这份索引；第二个 ERP 不复用第一个文件夹。实现使用宿主已有的 `workspaces.create({ path })`、`sessions.create({ cwd })` 和 `uiWorkspace.openSession`。宿主按规范 cwd 把会话归入该 Workspace，因此同一文件夹下可以再开一段对话；切换走宿主工作区列表，插件不另造会话树。桌面若没有注入 `workspaces`，文件夹仍建在插件数据目录，会话仍以该路径为 cwd，只是宿主列表里暂时看不到这个文件夹。

一键探索增加首次的模型调用和批准次数，换的是马上可读取的深度 3 索引。登录未完成时用户看见的是暂停和已有的部分结果。覆盖率仍只描述这一轮，不以未知功能为分母。

分享包可以离开这台机器，所以默认比备份更窄。接收方得到的是待复核的解释，不是对方的登录态，也不是对方 ERP 上的写入权。备份仍包含与数据库相同的私人业务信息，只用于本机或换机恢复。

第 1 版读者在第 2 版发布时要同时接受 1。只加可选键、不升主版本。升主版本的包必须能被旧读者整包拒绝，而不是读出半份知识。
