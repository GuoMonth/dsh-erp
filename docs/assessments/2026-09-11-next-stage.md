# 下一阶段推进后的对抗式评估

日期：2026-09-11。范围：版本化知识基础及受控只读导航增量。结论：知识积累与查询已具备可重复验证的工程链路；导航机制可以用于已知页面的受控实验，但还不具备通用 ERP 自动全局探索的条件。M1 未完成，#7/#8 不因合成测试通过而关闭。

本地完整验证已通过 58 项测试及安装包/真实 dsh CLI 冒烟；新增导航正负向测试使用合成站点。当时远端 CI 结果以对应 PR 当前提交的检查为准。2026-09-12 起改为[本地交付检查](../development.md#本地交付检查)，本评估保留历史基线。

## 当前能做什么

| 能力 | 当前证据 | 判断 |
| --- | --- | --- |
| 本机安装、浏览器登录/接管 | Node 24、真实 dsh rc2 CLI、实际 Chromium 与安装包验证 | 运行基础可用；干净机器及多平台首装仍待验证 |
| 原始观察 → 菜单/领域知识 → 双向查询 | SQLite、原生工具、版本/范围隔离、证据、重启及恢复测试 | 数据链路可用，真实模型理解质量未知 |
| 已知只读页面读取 | 精确请求契约、临时上下文、宿主许可及正负向测试 | 可用于开发者受控实验；默认不配置，不作为通用浏览能力 |
| L1/L2 全局探索 | 尚无持久化广度调度及菜单点击路径 | 仍是主要产品缺口 |
| 字段状态、业务行为、可复用查询/写入 | 字段样本可存储，行为执行和真实结果核验尚无 | 不能把数据结构支持理解为能力已经学会 |

## 对抗审查

**质疑一：是不是又在堆安全框架，偏离“效果第一”？**

有这个风险。本轮机制证明了“无契约不执行”“未知请求拒绝”“取消和人工接管后不沿用许可”，但不能替代业务效果。继续扩展静态清单、规则 DSL 或每个页面的手工适配，容易把项目做成需要维护的脚本集。建议把当前模式限制为实验与对照执行器；下一轮必须拿真实菜单任务衡量产出，不以更多基础设施测试数替代产品进度。

**质疑二：独立上下文是不是已经保证只读？**

没有。它隔离的是客户端持久状态，仍使用相同服务端登录身份。测试专门把写入型 GET 错列为只读，服务器确实发生了模拟修改。可信分类和服务端只读权限是前提；用户同意“读取菜单”不能替代具体业务变更批准。浏览器网络路径也没有全部经过验证，因此 #7 的全通道关闭标准仍未满足。

**质疑三：这些规则是否让用户安装后根本用不了？**

普通被动观察和知识查询不需要规则文件；新增导航入口默认不配置。若把规则文件变成普通用户首装必填项，就不符合“方便单机启动”。未来可以由 AI 辅助从可靠接口/实现证据生成候选契约，集中复核；前提是实测能降低维护成本，不能自动把流量观察变成许可。

**质疑四：能够打开两个 URL，是否就能探索 ERP 菜单？**

不能。当前按已知路由读取，未解决无独立 URL 的按钮、Tab、多级弹窗、动态身份去重及先广后深调度。临时上下文还可能改变 SPA 认证、缓存和页面表现。不能将路线清单视为独立菜单清单，或把已知路由读取成功计作全局覆盖。

**质疑五：知识模型是否已证明 AI 能理解业务？**

没有。证据引用和版本校验可以排除一部分数据错误，无法判断“采购入库属于库存与履约”的解释是否成立。需要同一角色的独立人工结构清单、跨菜单业务问题及字段解释期望，与真实模型输出对照。

## 下一轮应如何推进

1. **先完成一个真实只读切片。**明确测试企业/角色和服务端只读权限，用人工独立清单选首页一级菜单和两个跨菜单页面；记录目标构建、模型、耗时、缺口及正确/部分/错误结果。已有账号不能仅因能登录就判为只读。
2. **优先试真实 ERP 的认证与 SPA 兼容性。**确认 Cookie/localStorage 是否足够、是否依赖 Bearer/IndexedDB/sessionStorage、是否有可独立读取的页面路由。若本轮执行器不适用，应尽早调整或放弃这条导航方式，避免扩大请求清单硬凑。
3. **同步准备 #9 的持久化广度队列。**基于已有菜单身份、关系和任务检查点，先验证一级入口公平覆盖、层次门槛、预算暂停及重启恢复；执行器通过只读验收后再连接自动导航。局部任务不能关闭全局轮次。
4. **继续 #4 的效果对照。**在相同角色/数据及尽量一致的模型条件下，对照 Node/Playwright 与 browser-use 的实际任务成功、人工介入、恢复和成本。尚无证据证明应引入 Python，也无证据证明 Node 执行效果必然领先。
5. **此阶段不开放 ERP 业务写入。**具体变更对象、字段内容、范围、失效条件、批准、执行及回读尚未实现；当前读许可不能复用为写权限。

## 阻塞及非阻塞

真实验收仍缺企业/角色与只读权限确认、独立人工样本、真实模型运行条件，以及目标应用只读语义依据。它们阻塞真实效果结论和自动执行上线，不阻塞知识阅读视图、广度调度与恢复逻辑的离线开发。

本轮没有访问真实 ERP，没有新增生产策略，没有做真实 ERP 业务写入。具体机制和可复现测试见 [受控只读导航](../controlled-read-navigation.md)，真实知识切片的准备步骤见 [首轮知识验收](../testing/knowledge-round.md)。本报告是阶段判断，不是首版验收通过报告。
