# alpha.5 系统配置与知识复用验证

日期：2026-09-13。此记录对应系统入口改造 PR 的本地源码与预编译 TGZ，不表示 alpha.5 已发布到 npm。alpha.4 的发布验收见[此前记录](2026-09-13-installation.md)。

## 已实现

- DSH profile patch 持久保存入口、可选应用 Base URL、名称和身份别名；未配置时插件仍可启动，返回配置指引。
- `erp_system_status` 在无浏览器状态下返回固定系统 ID、精确 scope 和实际目录。知识、证据、学习检查点使用系统目录；其他身份 scope 在存储调用边界被拒绝。
- `erp_scm_connect` 不接收 URL/scope 参数，原样打开配置入口，取消根路径与固定 `/#/login` 假设。用户自行登录，确认当前身份后授权固定 SCM 读取。
- 相同应用重启、改名、修改登录 hash 保留 ID；不同应用路径建立独立目录。旧库保留，未配置 system 时仍能查询、导出和备份；不做隐式迁移。
- 英文 npm README、中文指南、配置/存储/知识/学习/浏览器/路线说明及 GitHub Release 说明生成模板对齐。版本推进到 alpha.5，发布仍需合并后手动执行 Action。

首次使用验证发现：DSH 默认 patch 是注释加 `[]`，直接追加 YAML 条目会解析失败。测试改为替换空列表；中英文用户指南明确该操作，保留已有条目并合并已有 erp config。

完整验证中的首次安装 smoke 曾因上述测试文件写法失败；修正后单独重跑 `npm run smoke` 通过。记录的通过结果来自修正后的组件检查，不把那次失败的 `npm run verify` 描述为成功运行。最终专项命令为 `node --test tests/system.test.mjs`。

## 尚未验证或暂缓

此次未使用真实 ERP 账号或真实模型重新跑业务链；未验证二维码、跨域 SSO、Windows/macOS、全新操作系统依赖安装或默认沙箱桌面路径。已有真实 ERP 基线仍属于 alpha.1，不能由配置测试推导新的适配范围。

每实例一个系统和共享浏览器，不实现多对话各自浏览器、多 ERP 自动路由、多个进程同时共享 SQLite、域名别名合并或旧知识自动迁移。账号/企业/角色需要用户确认，不能自动发现后台静默切换身份。学习仍是菜单优先及显式任务队列，不能承诺一个 URL 下全部页面或业务行为已学习。

发布后还需按精确 alpha.5 从 npm 安装，核对 registry/GitHub 产物并记录配置行为；本次 PR 不自动发布或增加 CI。
