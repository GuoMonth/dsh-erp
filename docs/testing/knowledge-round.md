# 首轮真实知识验收准备

本轮目标：在人工作为浏览器操作者的条件下，验证插件保存的观察能形成可追溯的菜单—业务关系，并在重启后回答同样的问题。此轮不等于自动全局探索验收。

## 当前关口

目标站点已经完成独立登录探测；当前插件的浏览器、知识、迁移和宿主链路只有合成环境证据。企业/角色及账号是否只读待用户确认，真实模型路由和独立人工清单待登记。未知项保持未知，不默认现有账号拥有安全的只读权限。

不需要重新提供账号密码，也不将其写入 target.json、知识记录或公开报告。登录仍由用户在专用浏览器中完成，平台窗口与证书环境沿用 [浏览器说明](../browser-observation.md)。

## 有界执行顺序

1. 固定本次构建、scope 别名、语言、模型路由和观察时间；记录条件差异，不填写模型密钥。
2. 人工登记当前角色可见的一级入口及两个存在关联的页面，使用既有 menu-inventory.csv。独立清单在 Agent 学习前保存，不从 Agent 输出反推期望。
3. 使用插件专用窗口登录，确认当前企业/角色。首页先做被动观察，形成一级入口骨架；未知和未观察分支分别记录，不能宣称全站完成。
4. 人工按已确定的无写入风险路径查看两个页面。每次人工输入或导航后观察会暂停，需重新确认当前会话范围；插件不为本轮新增自动点击能力。
5. Agent 先检索历史记录和别名，再创建菜单/页面及证据引用，另建一个业务域假设，用关系连接页面。字段有实际观察证据才记录；当前标签采集不读取表格值，不凭空填写状态值域。
6. 从菜单查询业务域，再从业务域返回两个页面及证据；解释必须区分观察事实、假设、用户修订和命题确认。
7. 用户纠正一项解释，检查原始观察和旧版本仍可回查。重启插件后重复查询，再做备份恢复到新目录核对。

## 通过证据与停止条件

| 核验 | 应保留的结果 |
| --- | --- |
| 范围与结构 | 构建、模型/语言、scope、人工入口清单、插件发现/遗漏/阻塞；不以自发现数量证明完整 |
| 双向关联 | 菜单/页面与域的稳定 ID、关系版本、逐字观察引文、解释与未知项 |
| 修订 | AI 版本、具体用户修订、对应确认、旧观察；不能把用户认可解释写成行为测试通过 |
| 重启/恢复 | 同 scope/ID 的记录、关系、版本与证据一致；浏览器会话不属于 SQLite 备份 |
| 效果 | 各问题预期与实际答案、正确/部分/错误/阻塞；记录耗时和模型消耗，未知费用写 null |

登录/范围不确定、页面出现未知副作用、用户接管或预算不足即停止本轮对应动作并记录原因。只完成首页或两个页面时只能报告该范围；#9/#10 的自动广度探索仍须另行验收。

原始地址、账号、业务资料和页面证据放本地 artifacts/；公开 PR 只保留合成样本和脱敏结论。尚未执行上述真实验收，不提前填写通过结果。
